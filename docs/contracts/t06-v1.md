# T06 Odontogram API contract v1

Status: ready for Luna3 integration. This contract is based on the existing
`frontend/src/odontogram/` component. Any incompatible change must be announced
and versioned before the UI adapter is changed.

All endpoints are under `/api/odontogram`. Requests require a bearer token.
Clinic identity always comes from the authenticated user; callers cannot select
or override `clinic_id`.

## Identifiers and enums

- `patientId`, `findingId`, `revisionId`, `actorId`: UUID strings.
- `toothId`: two-digit FDI permanent tooth code: 11–18, 21–28, 31–38, 41–48.
- `status`: `present | missing | unevaluated`.
- `surface`: `mesial | distal | buccal | lingual | palatal | occlusal | incisal | vestibular | labial | approximal | interproximal`.
- `finding.status`: `draft | finalized`.
- Timestamps are ISO-8601 UTC strings. Actor display names are server supplied.

## Read a patient odontogram

`GET /api/odontogram/patients/{patientId}`

Returns all 32 adult teeth in FDI order, including `unevaluated` teeth, plus
visible findings and their revision history. Draft findings are visible only
to their author. `history` contains `finding_added`, `finding_corrected`, and
`status_changed` events with `id`, `toothId`, `occurredAt`, `author`, `summary`,
and previous/current values for changes. A patient outside the caller's clinic
returns 404.

```json
{
  "patientId": "11111111-1111-4111-8111-111111111111",
  "teeth": [{"toothId":"16","status":"present","updatedAt":"2026-11-11T09:00:00Z","updatedBy":{"id":"22222222-2222-4222-8222-222222222222","name":"Dr. Mara Ionescu"}}],
  "findings": [{"id":"33333333-3333-4333-8333-333333333333","toothId":"17","kind":"caries","description":"Suspiciune pe șanțul central","surfaces":["occlusal"],"status":"draft","observedAt":"2026-11-11T09:05:00Z","createdAt":"2026-11-11T09:05:00Z","authorId":"22222222-2222-4222-8222-222222222222","author":"Dr. Mara Ionescu","revisions":[]}],
  "history": [{"id":"44444444-4444-4444-8444-444444444444","toothId":"17","occurredAt":"2026-11-11T09:05:00Z","author":"Dr. Mara Ionescu","kind":"finding_added","summary":"Constatare adăugată: caries"}]
}
```

## Change a tooth state

`PUT /api/odontogram/patients/{patientId}/teeth/{toothId}`

```json
{"status":"missing"}
```

Returns the current tooth plus `previousStatus`, `updatedAt`, and `updatedBy`.
Repeating the same state is idempotent and creates no duplicate revision.
Changing a state records its previous and new values in persistent history.

## Create a finding

`POST /api/odontogram/patients/{patientId}/findings`

```json
{"toothId":"17","kind":"caries","description":"Leziune suspectă pe șanțul central","surfaces":["occlusal"],"observedAt":"2026-11-11T09:05:00Z","status":"draft"}
```

`kind` and `description` are required; `surfaces` defaults to an empty array,
must contain unique valid values, and `observedAt` defaults to server time.
New findings default to `draft`, owned by the authenticated doctor. An optional
`Idempotency-Key` UUID makes a retried create return the original finding.
Response includes server `id`, `createdAt`, `author`, and an empty `revisions`.

## Update or finalize a finding

`PATCH /api/odontogram/findings/{findingId}` supports draft edits by its author:

```json
{"kind":"caries","description":"Confirmată clinic","surfaces":["occlusal","mesial"]}
```

`POST /api/odontogram/findings/{findingId}/finalize` finalizes the author's
draft. Finalized findings are immutable. A draft is invisible and inaccessible
to every other user, including managers and administrators.

## Correct a finalized finding

`POST /api/odontogram/findings/{findingId}/corrections`

```json
{"kind":"caries","description":"Leziune pe suprafața mezială","surfaces":["mesial"],"reason":"Reevaluare la control"}
```

Creates an append-only revision with previous/current values, reason, `actorId`,
`author` and server timestamp. The response contains the updated current finding and the
revision list; prior values remain available. Doctors, clinic managers and
administrators may make clinical changes within the rules below. A finalized
finding can be corrected by its author or a manager or
administrator; drafts remain author-only without administrative exception.

## Roles and errors

- `clinic_manager`, `doctor`, `administrator`: read odontograms and create,
  update and correct clinical data, subject to draft ownership above.
- `assistant`, `reception`: no odontogram access; this does not expand their
  clinical permissions.
- `401`: missing/invalid authentication; `403`: insufficient role or draft
  ownership; `404`: patient/finding absent or outside clinic; `409`: attempted
  edit of finalized finding or stale state conflict; `422`: invalid FDI,
  surface, enum or payload.

Selecting a tooth and recording a finding do not create a procedure, price,
appointment, or timer.
