# T13 v1 — cont intern al pacientului: servicii efectuate, încasări, ajustări, sold

Status: pilot local, date fictive. **Evidență internă. NU este facturare fiscală, bon/chitanță fiscală, integrare
contabilă sau plată online.** O singură monedă: RON (moneda catalogului T03; catalogul acceptă azi numai RON).

## Model

- **Servicii efectuate = proiecție, nu copie.** Se citesc manoperele T04 ale pacientului cu `status = completed`, la
  `current_price` (snapshotul tarifului din catalog la creare + override-ul managerului prin
  `POST /api/performed-procedures/{id}/override-price`, cu revizia T04 existentă). Dacă `current_price` lipsește
  (date vechi), se folosește `procedure_base_price`. `pending/running/paused` apar ca „în lucru” fără sumă,
  `cancelled` apare „anulată, fără sumă”; niciuna nu intră în datorat. Fluxul T04 nu este modificat.
- **Mișcări** (`patient_financial_entries`), imuabile: API-ul nu are UPDATE/DELETE (rutele PATCH/PUT/DELETE nu există).

| Câmp | Regulă |
|---|---|
| `kind` | `payment` (încasare/avans), `refund`, `adjustment_credit` (scade datoria), `adjustment_debit` (crește datoria), `reversal` |
| `amount` | `Numeric(12,2)`, > 0; API: șir zecimal `^\d{1,10}(\.\d{1,2})?$` (numerele JSON sunt refuzate pentru exactitate) |
| `currency` | `RON` (implicit; altă monedă → 422) |
| `method` | obligatoriu pentru payment/refund: `cash \| card \| transfer \| other` (etichetă internă); interzis pentru celelalte |
| `reason` | obligatoriu (ne-gol) pentru refund, ajustări și reversal; opțional la payment |
| `appointment_id` | opțional; vizita trebuie să fie a aceluiași pacient și a aceleiași clinici, altfel **422** |
| `reverses_entry_id` | numai la `reversal`; o mișcare se anulează **o singură dată** (index unic parțial); un reversal nu se poate anula (409) |
| `client_request_id` | UUID generat de client per formular, unic per clinică; retrimiterea aceluiași id cu același conținut întoarce mișcarea existentă (**200**), cu alt conținut **409** |
| `clinic_id`, `created_by_id`, `created_at` | derivate pe server; ora este UTC cu offset explicit în API |

Un reversal copiază suma, moneda, pacientul și vizita mișcării anulate, fără metodă. Fiecare mișcare scrie un
`AuditEvent` (`entity_type = financial_entry`, `action = kind`).

## Sold

`sold = servicii completed + adjustment_debit − adjustment_credit − payment + refund`, unde mișcările anulate printr-un
reversal nu se mai numără (iar reversal-ul nu se adună separat). Calcul exact cu `Decimal`. `balance_status`:
`due` (> 0), `settled` (0), `credit` (< 0 = avans/credit al pacientului, afișat explicit). O rambursare mai mare decât
încasările nu este blocată (rămâne trasabilă cu motiv); limită acceptată în pilot.

## Roluri (din `app/auth/service.py`)

| Acțiune | Roluri |
|---|---|
| citire cont, sumar vizită | toți: reception, clinic_manager, administrator, doctor, assistant |
| payment, refund, reversal de payment/refund | reception, clinic_manager, administrator |
| adjustment_credit/debit, reversal de ajustare | clinic_manager, administrator |
| raport zi | reception, clinic_manager, administrator |

Rol nepermis → **403**. Pacient/mișcare/vizită din altă clinică → **404** (pacient, mișcare, sumar vizită); o vizită
străină trimisă ca referință la creare → 422 (nu confirmă existența).

## API (`/api/finance`)

| Metodă și rută | Descriere |
|---|---|
| `GET /patients/{id}/account` | totaluri (servicii, încasări, rambursări, net, ajustări, sold, status), servicii pe vizită, mișcări cu autor/oră și anularea lor, permisiunile rolului curent |
| `POST /patients/{id}/entries` | `{kind, amount, currency?, method?, reason?, appointment_id?, client_request_id}` → 201 (sau 200 la retry) |
| `POST /entries/{id}/reverse` | `{reason, client_request_id}` → 201 / 200 retry / 409 deja anulat sau reversal |
| `GET /appointments/{id}/summary` | servicii completed ale vizitei, încasat net legat de vizită |
| `GET /daily?date=YYYY-MM-DD` | ziua în **fusul clinicii** (interval UTC întors în `range`), net pe metodă: payment +, refund −, reversal de payment −, reversal de refund +; reversal de ajustare nu mișcă bani |

## Concurență

- Reversal: rândul mișcării anulate este blocat (`SELECT … FOR UPDATE`); două anulări simultane se serializează, a doua
  vede anularea comisă → 409. Indexul unic parțial pe `reverses_entry_id` este a doua barieră.
- Idempotency: verificare prealabilă + constrângerea unică `(clinic_id, client_request_id)`; inserarea care pierde
  cursa face rollback și întoarce mișcarea existentă (200).
- Dovezi: `backend/tests/test_postgres_finance.py` (în selecția PG din CI).

## UI

- Panoul **„Cont pacient”** pe pagina pacientului, pentru toate rolurile de personal, cheie `${patientId}:account`.
  **Abatere de la fișă:** nu este montat în `ClinicalPatientRecord`, pentru că acel component este afișat numai rolurilor
  clinice (doctor/manager/admin) și recepția, principalul utilizator T13, nu l-ar vedea. Este montat imediat înaintea
  dosarului clinic, fără a muta celelalte panouri.
- Totaluri servicii / încasat net / sold (credit explicit), servicii pe vizită, mișcări cu autor și oră în fusul clinicii,
  formular cu validare locală (sumă, metodă, motiv), `client_request_id` per formular păstrat la eroare și reînnoit după
  succes, buton dezactivat și gardă sincronă contra dublului click, anulare cu motiv și confirmare. Doctor/asistent: numai citire.
- Pagina vizitei: suma serviciilor completate ale vizitei, încasat pe vizită, încasare rapidă legată de vizită (roluri cu încasare).
- Pagina **„Încasări zi”** (`/finance/daily`) pentru recepție/manager/admin.
