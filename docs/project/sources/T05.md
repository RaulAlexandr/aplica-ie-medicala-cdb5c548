# T05: dosarul pacientului și cronologia

Dependență: commitul T04 rezultat din taskul anterior. T05 se implementează într-un branch derivat, cu diferență separată față de T04.

## Rezultat

Din dosarul pacientului, utilizatorul autorizat vede datele personale și medicale existente, alertele, vizitele și manoperele T04, note și constatări. Poate reconstrui cine a făcut ce, când, în ce context și ce s-a corectat. Nu recrea Patient sau PatientRevision existente.

## Domeniu

- Expune în UI câmpurile relevante Patient deja implementate: identitate/contact, medicale, alergii, medicație, afecțiuni, sarcină/fumat, intervenții, alerte și note, cu permisiunile server-side existente păstrate.
- Arată reviziile existente în UI autorizat; nu acorda acces recepției/asistenților doar pentru că văd lista pacienților.
- Adaugă note clinice și constatări distincte de proceduri. Pot avea pacient, vizită opțională și localizare FDI/suprafețe; adăugarea lor nu pornește cronometre și nu creează manopere.
- Drafturi salvabile și reluabile. Propunere de lifecycle: draft → finalizat; după finalizare, corecție/addendum cu motiv și autor, fără suprascrierea versiunii vechi. Stabilește și documentează vizibilitatea drafturilor; minim, autorul le accesează, iar rolurile administrative nu primesc automat acces suplimentar fără justificare.
- Timeline din evenimente reale ale modulelor implementate: programări și istoric, execuție T04, note/constatări și corecții, revizii pacient autorizate. Distinge data clinică a evenimentului de data introducerii/corecției, inclusiv pentru date retrospective.
- Timeline paginat cu ordine stabilă și criteriu de departajare. Filtre pe tip și interval de date; afișare în fusul clinicii. Păstrează sursa și legătura la înregistrarea reală, evită dubluri la agregare și după reîncărcare.
- Definește dacă timeline-ul este o proiecție din istorice existente sau are evenimente proprii. Dacă persiști evenimente noi, scrierea lor este tranzacțională și rezistentă la retry. Nu folosi auditul incomplet drept substitut al istoricului clinic.
- Alertele medicale relevante sunt vizibile în dosar și în contextul vizitei pentru rolurile autorizate, fără a le expune prin endpointuri publice sau roluri fără acces.

## Ce NU construiești aici

Odontograma grafică T06, cele două intrări T07, planurile T08, parodontologia T09/T10, uploadul de documente T11, formularele T12 și plățile T13. Timeline-ul va putea primi aceste evenimente ulterior; nu fabrica acum evenimente, stări complete sau endpointuri goale pentru module inexistente. Nu pretinde Patient 360 complet pentru funcționalități viitoare.

## Politică și integritate

Documentează matricea de roluri și câmpuri. Clinic_id din sesiune, patient_id și toate referințele validate pe server. Un URL ghicit nu permite acces la altă clinică. Nu permite schimbarea clinicii/pacientului unei note prin PATCH. Păstrează istoricul corecțiilor; nu implementa ștergere distructivă a înregistrărilor finalizate. Sanitizarea/renderizarea notelor nu execută HTML introdus de utilizator.

## UI și API

Dosar navigabil din lista de pacienți și din programare. Secțiuni pentru date, alerte, timeline și istoricul autorizat; formulare de note/constatări și drafturi. Linkuri spre vizitele/manoperele T04. Listele lungi au paginare utilizabilă, iar filtrele și starea formularelor se resetează corect la schimbarea pacientului.

Nu modifica politica existentă de editare Patient implicit. Orice extindere necesară este o decizie explicită în raport. Păstrează API-urile existente compatibile și contractele frontend sincronizate.

## Dovezi cerute

- Dosarul arată câmpurile persistate și reviziile existente, cu acces corect pe rol.
- Draft salvat → reload → reluare → finalizare → corecție; versiunea veche rămâne inspectabilă.
- Constatare pe alt dinte în timpul unei manopere: zero manopere/timere suplimentare create.
- Timeline corect pentru programare, manoperă finalizată, notă, constatare și corecție, cu actor și sursă.
- Paginare stabilă la timestampuri egale și filtre corecte în fusul clinicii, fără dubluri accidentale.
- Notele/istoricul protejat nu se scurg prin listări, count, căutare sau timeline pentru roluri neautorizate.
- Cross-clinic pentru read/create/update/history și referințe către vizite/manopere.
- Migrare din T04 populat păstrează pacienții, reviziile și manoperele.
- Build, backend/frontend tests și regresiile T04 trec; probe browser unde mediul permite.

Livrarea finală include SHA-ul T04 de bază, SHA-ul T05 final și raport separat. Fără merge sau deploy.
